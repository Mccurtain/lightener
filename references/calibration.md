# 标定（Calibration）· 维护者文档

> 判断物品时不需要读这份。只有**改规则 / 改阈值 / 加样例**时才打开。

## 为什么需要

阈值（70 / 55 / 40 / 25）和权重（0.25 / 0.20 / 0.15 / 0.15 / 0.15 / 0.10）最初都是拍脑袋定的。没有真实案例验证前，系统只是"看起来严谨"，不等于"结论正确"。标定就是把系统结论和人工判断对齐的过程。

## 怎么用

样例数据在 `scripts/calibration_samples.json`，每条包含：

- `name`：物品名
- `scores` / `category`：部分或全部维度，与正式输入格式一致
- `expect`：人工判断的应有结论
- `why`：为什么是这个结论（改规则时用来判断谁错了）

运行：

```bash
python scripts/calibrate.py                      # 逐条列出 期望 / 实际 / 分数
python scripts/calibrate.py --quiet              # 只显示不符项
python scripts/calibrate.py --preset minimalist  # 换权重方案跑
python scripts/calibrate.py --economy tight      # 换经济档位跑
```

退出码 0 表示全部相符，1 表示存在不符——**改动任何规则或阈值后都应重跑**。

当前状态：四套权重方案 × 三档经济水平 **全部 30/30 相符**。不符时先判断是样例期望写错，还是规则真的有问题。

改动规则后的标准顺序：`python scripts/build_form.py` → `python scripts/calibrate.py` → 重新打包。

## 当前结果

| 权重方案 | 结果 | 说明 |
|---|---|---|
| `balanced` | 30 / 30 | 基准，全部相符 |
| `minimalist` | 30 / 30 | 全部相符 |
| `sentimental` | 30 / 30 | 全部相符 |
| `space` | 30 / 30 | 其中 3 条用 `expect_by_preset` 单列期望：不占地方的小件（保修卡、数据线、塑料袋）在空间优先下被延后处理，属方案本意 |

标定以 `balanced` 为准。其他方案出现差异时，先判断差异是否可由该方案的偏好解释——能解释就是设计意图，写成该方案的 `expect_by_preset`；不能解释才是缺陷，要改规则。

`expect_by_preset` 只在该方案下覆盖期望值，不改变 `balanced` 的基准，也不掩饰规则问题：新增时必须同时写清 `why`，且不得用它把明显错误的结论"洗白"。

`expect_by_economy` 同理，用于**金额意义随档位变化**的样例：WTP 检验那条单反在常规档是暂存观察，在预算敏感档是保留（观察）——不是规则坏了，是同一个"一百块"对不同人的分量不同。

四套方案 × 三档经济水平（tight / normal / comfortable）当前全部 30 / 30。

除样例回归外，`calibrate.py` 还跑两项检查：**文档一致性**（SKILL.md 品类速查表 vs `CATEGORY_PRIORS`）与 **WTP 换算**（同一金额在不同经济档位下落到不同替代难度分）——后者守住"愿意付的钱才是真实估价"这条换算链。

其中 2 条是**后悔管理**的回归样例：同一件登山杖写 `"swings": 1` 应落到封存观察，`"swings": 2` 应停在封存且锁定——摇摆阶梯一旦被改坏，这里会立刻红。

另有 2 条是**附属件联动**（狄德罗效应的反面）的回归样例，依赖同批主件"旧手机（数据已备份）"的结论：贴膜神器应随主件清零到建议流转，情感 ≥4 的纪念手机壳应停在封存观察。改样例时不要动主件的名字——`depends_on` 靠它匹配。

## 标定改出了什么

首轮标定暴露了四个真实缺陷，都已修进规则：

1. **"还能用且有人要"的东西被判丢弃** —— 旧手机、书。补规则：功能 ≥3 且替代 ≥2 → 不做丢弃结论（替代阈值从 3 下调到 2，覆盖书这类不值钱但能送人的东西）。
2. **高情感物品被判转赠** —— 亡父的手表在极简方案下成了"建议流转"。补规则：情感 ≥4 → 不丢也不转赠，封存观察。
3. **未来需求明确的物品被误判** —— 计划二胎的婴儿床。补规则：未来需求 ≥4 → 结论不低于暂存观察。
4. **闲置物品靠"新"和"贵"撑分** —— 不合身的贵价西装停在"暂存观察"。补了闲置折半：长期闲置且情感不高时，功能状态与替代难度贡献减半。

另外把 `cable`（线材）品类的基线从"使用 2 / 未来 3"下调为"使用 1 / 未来 2"——一箱旧线不该按"最近几个月用过"计。

## 新增样例的原则

1. 样例要覆盖**边界**，不要只挑明显的：正好落在阈值附近的最有价值。
2. `why` 必须写清楚，否则下次不符时无法判断是规则错还是期望错。
3. 期望结论按"一个正常人会怎么处理"来定，不要迁就当前系统的输出——否则标定就失去意义。
4. 覆盖各类硬规则的触发情形：安全、过期、凭证、不可修复、情感 0、情感 5、未来明确。
